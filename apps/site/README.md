# site

The public page for megha: what it is, a T3 thread that plays out in the cloud, and a one-line setup prompt.

```
PORT=3417 bun run dev     # from the repo root: bun run dev
bun run test              # setup.md, the prompt and the config snippets (bun test)
bun run lint
bun run typecheck
bun run build
```

- `app/` holds routes only. Feature code lives in `features/<name>/`.
- `public/setup.md` is what an agent follows to install megha, served at `/setup.md`. The copied prompt is one
  line that points at it. `features/install/install.ts` holds that prompt, the manual steps and the T3 and Zed
  snippets; `install.test.ts` fails if setup.md and the snippets disagree or the safety rules go missing.
- `features/thread-demo/script.ts` is the demo's content and timeline. The server renders the finished thread;
  the client plays it as a CSS timeline.
- The look is written down in `.critly/direction.md`. Tokens and every keyframe are in `app/globals.css`.
- Below-the-fold sections fade in on scroll, so a full-page screenshot taken without scrolling shows them
  blank. Scroll through first, or use reduced motion.
- Favicons in `app/` are generated by `assets/icons/build.mjs` (`bun run icons`).
